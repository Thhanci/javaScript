## 思路

### 1、constructor()

```js
constructor() {
    this.events = {};
}
```

创建一个对象保存所有事件。

```js
this.events = {
    click: [fn1, fn2],
    login: [fn3]
}
```

* key：事件名
* value：回调函数数组

> **注意：代码中 `this.eventsp` 写错了，应改为 `this.events`。**

---

### 2、subscribe()

#### （1）事件不存在就创建数组

```js
if (!this.events[eventName]) {
    this.events[eventName] = [];
}
```

第一次订阅：

```js
subscribe("click", fn1);
```

变成：

```js
{
    click: []
}
```

---

#### （2）保存回调函数

```js
this.events[eventName].push(callback);
```

例如：

```js
click: [
    fn1,
    fn2
]
```

以后 `emit()` 时按顺序执行。

---

#### （3）记录当前函数下标

```js
const index = this.events[eventName].length - 1;
```

方便以后 `unsubscribe()` 删除。

---

#### （4）返回取消订阅对象

```js
const sub = emitter.subscribe("click", fn);

sub.unsubscribe();
```

---

### 3、unsubscribe()

#### 删除当前回调

```js
this.events[eventName].splice(index, 1);
```

`splice(开始位置, 删除数量)`

例如：

```js
[
    fn1,
    fn2,
    fn3
]
```

执行：

```js
splice(1, 1);
```

结果：

```js
[
    fn1,
    fn3
]
```

如果数组为空：

```js
delete this.events[eventName];
```

直接删除整个事件。

> 更推荐：

```js
this.events[eventName] =
    this.events[eventName].filter(fn => fn !== callback);
```

`filter()`：保留满足条件的元素，删除不满足条件的元素。

例如：

```js
[
    fn1,
    fn2,
    fn3
]
```

删除 `fn2` 后：

```js
[
    fn1,
    fn3
]
```

相比 `splice(index, 1)`，不会因为数组下标变化而删错元素。

---

### 4、emit()

#### （1）没有事件直接返回

```js
if (!this.events[eventName]) {
    return [];
}
```

---

#### （2）遍历所有回调并执行

```js
const callbacks = this.events[eventName];

for (let i = 0; i < callbacks.length; i++) {
    const result = callbacks[i].apply(null, args);
    results.push(result);
}
```

`results` 用来保存所有回调函数的返回值。

---

#### （3）apply()

```js
callback.apply(null, args);
```

等价于：

```js
callback(...args);
```

例如：

```js
emit("add", [3, 5]);
```

实际执行：

```js
callback(3, 5);
```

如果：

```js
emit("click");
```

由于：

```js
emit(eventName, args = []);
```

`args` 默认是空数组，所以实际执行：

```js
callback();
```

---

## 整体流程

```text
subscribe()
      ↓
events 保存回调

emit()
      ↓
遍历回调并执行
      ↓
返回所有回调的结果

unsubscribe()
      ↓
删除对应回调
```


















## 为什么 `length - 1` 不推荐？

原来的写法：

```js
const index = this.events[eventName].length - 1;
```

表示**订阅时**记录当前回调所在的下标。

例如：

```js
[
    fn1,
    fn2,
    fn3
]
```

三个订阅对象分别保存：

```text
sub1 -> index = 0
sub2 -> index = 1
sub3 -> index = 2
```

刚订阅时，下标都是正确的。

---

### 问题：数组会变化

如果先删除 `fn1`：

```js
[
    fn1,
    fn2,
    fn3
]
```

执行：

```js
sub1.unsubscribe();
```

数组变成：

```js
[
    fn2,
    fn3
]
```

此时：

```text
fn2：1 → 0
fn3：2 → 1
```

所有元素的下标都会往前移动。

但是：

```text
sub2 里面保存的还是 index = 1
```

如果执行：

```js
splice(1, 1);
```

删除的是：

```text
fn3 ❌
```

真正应该删除的是：

```text
fn2 ✔
```

所以容易删错。

---

## 为什么使用 `indexOf()`？

改成：

```js
const index = this.events[eventName].indexOf(callback);

if (index !== -1) {
    this.events[eventName].splice(index, 1);
}
```

`indexOf()` 的作用：

> **查找元素当前所在的下标。**

例如：

```js
const arr = ["a", "b", "c"];

arr.indexOf("a"); // 0
arr.indexOf("b"); // 1
arr.indexOf("c"); // 2
arr.indexOf("d"); // -1（不存在）
```

如果数组已经变成：

```js
[
    fn2,
    fn3
]
```

那么：

```js
indexOf(fn2); // 0
indexOf(fn3); // 1
```

得到的是**当前最新的位置**，因此删除一定是正确的。

---

## 总结

* `length - 1`：记录的是**订阅时**的下标，数组删除元素后，下标会变化，容易删错。
* `indexOf(callback)`：删除时**重新查找**当前下标，不受数组变化影响，更安全、更推荐。
